# Математическая модель

Оценщик реализован в `tram_backup_odometry/tram_backup_odometry/baseline_estimator.py`. Он
получает входы от ноды по мере прихода сообщений и на каждый вход возвращает оценку состояния.

## Входы, состояние, выходы

Входы:

- `v_f`, `v_r` — показания передней и задней тележек. В записях это км/ч, хотя в описании
  датасета указаны м/с: отношение к эталонной скорости ровно 3,6.
- `u` — позиция контроллера водителя, целое от −15 до +15 (плюс — тяга, минус — торможение).
- GNSS master и rover — только первые 5 секунд, для начальной выставки.

Состояние:

- `v` — продольная скорость base_link, м/с;
- `a` — измеренное ускорение, м/с²;
- `D` — одометр, интеграл скорости, м;
- положение на карте: номер пути `pid`, дуговая координата `s`, направление движения
  `dir = ±1`;
- неопределённость положения вдоль пути `σ²`, масштаб колёс, множители модели тяги, отношение
  передней тележки к задней, флаги проскальзывания.

Выходы: скорость, положение `(x, y, z)` base_link в системе карты, курс и тангаж, ковариации,
флаг проскальзывания, относительное скольжение и оценка коэффициента сцепления.

## Скорость по тележкам

Показание тележки переводится в м/с с общим масштабом колеса:

```
v_i = k · raw_i,   k = 1.00034 / 3.6   (для трамвая 30639 — 1.00254 / 3.6)
```

Масштаб получен по 57 обучающим записям: путь по RTK на карте, делённый на путь по колёсам.

Передняя и задняя тележки калибруются относительно друг друга на ходу. Для этого берутся пары
показаний одного момента (тележки опрашиваются синхронно) на спокойных участках: обе быстрее
3 м/с, согласны между собой, проскальзывания нет, |a| < 0,5 м/с². По ним оценивается
`ρ = ln(v_f / v_r)` с памятью около 200 секунд. Передняя делится на `e^(ρ/2)`, задняя
умножается на `e^(ρ/2)`, так что средний масштаб не меняется. На имеющихся данных тележки и так
совпадают в пределах 0,01–0,05 %, поэтому блок нужен на случай обточки или замены колёс одной
тележки.

Ускорение считается как наклон скорости по времени самих измерений. Опорная точка `(t₀, v₀)`
сдвигается, когда прошло не меньше 0,04 с:

```
a ← a + (Δv/Δt − a) · min(1, Δt / 0.4),   Δv = v − v₀,  Δt = t − t₀
```

Так учитываются и измерения, пришедшие «из прошлого»: сообщение одной тележки иногда старше
последнего обработанного. Проверка на эталоне проверочной записи: ускорение совпадает с
производной эталонной скорости с коэффициентом 0,97 и ошибкой 0,075 м/с².

Каждое новое показание сравнивается с прогнозом:

```
v̂ = v + a_p · Δt,   a_p = clamp(a, A − 0.3, A + 0.3),   |v_i − v̂| ≤ 0.4 + 2.0 · Δt  (м/с)
```

Здесь `A` — ускорение по модели тяги (следующий раздел). Ограничение прогноза моделью нужно,
чтобы строб не «уезжал» вслед за колесом, которое начало буксовать. Дальше:

- обе тележки в стробе — берётся среднее;
- одна — берётся она, вторая помечается как проскальзывающая или отказавшая;
- обе вне строба — шаг к ближайшей, но не больше физического предела ускорения
  (+1,8 / −3,2 м/с²). Если тележки согласны между собой дольше секунды, оценка переходит к ним.

Новая скорость действует с середины интервала между измерениями, и одометр `D` поправляется на
это задним числом. На выход скорость подаётся с задержкой 30 мс: эталон слегка запаздывает
относительно колёс.

## Модель «позиция контроллера → ускорение»

Позиция контроллера задаёт силу тяги или торможения привода. По второму закону Ньютона

```
m · dv/dt = F(u, v) − W(v) − m · g · sin θ
```

где `F(u, v)` — сила на ободе колёс (при высокой скорости тяга падает из-за ограничения
мощности), `W(v)` — основное сопротивление движению, `θ` — уклон пути. Массу и характеристику
привода по отдельности мы не знаем, поэтому модель записана для ускорения:

```
a = k_s · A(u(t − τ), v) − g · sin θ,   τ = 0.2 с
```

`A(u, v) = (F − W) / m` — таблица «на ровном пути»: 31 позиция контроллера на 9 интервалов
скорости (границы 0, 1, 3, 5, 7, 9, 11, 13, 15, 30 м/с), между узлами — линейная интерполяция по
скорости. Таблица построена по 96 обучающим записям. Бралась медиана измеренного ускорения в
ячейке, после того как из него вычтено `g · sin θ` по карте. Запаздывание привода τ подобрано
по минимуму ошибки прогноза. Таблицу сопротивления отдельно не держим: при нулевой позиции
(выбег) строка таблицы и есть `−W(v)/m`, от −0,01 до −0,07 м/с².

При загрузке таблица приводится к физическим ограничениям: тормозные позиции тормозят, тяговые
не тормозят сильнее сопротивления, стоящий на тормозе трамвай под уклон не катится.

Уклон берётся из высот карты по хорде между тележками (7,55 м) и ограничивается ±8 %. Остаток
модели с уклоном 0,202 м/с², без уклона — 0,221 м/с².

Множитель `k_s` учитывает загрузку вагона и состояние привода. Он оценивается на ходу
рекурсивным МНК с забыванием (память около 90 с), отдельно для тяги и торможения, по схеме
Vahidi, Stefanopoulou, Peng для одновременной оценки массы и уклона. Регрессор — табличное
ускорение, цель — измеренное ускорение плюс `g · sin θ`. Обновления идут только на чистых
участках: тележки согласны, проскальзывания нет, скорость больше 2 м/с, позиция держится не
меньше секунды, модель даёт заметное ускорение. Пределы `k_s` — от 0,6 до 1,5. После стоянки
дольше минуты уверенность сбрасывается: могла смениться загрузка.

Интегрирование — шагом `h = 0,1 с`:

```
v_{n+1} = min(max(v_n + a_n · h, 0), v_max),   D_{n+1} = D_n + (v_n + v_{n+1}) · h / 2
```

Модель работает в трёх местах: в прогнозе для строба, при пропадании колёсных данных и в
детекторе проскальзывания обеих тележек.

Две вещи мы проверили по данным и в модель не включили. Добавочное сопротивление в кривых по
норме 700/R ‰ дало бы −0,14…−0,27 м/с² при радиусе 25–50 м, но в данных остаток модели в таких
кривых такой же, как на прямой. Позиция −8 ведёт себя особо: первую секунду после установки
трамвай тормозит примерно на −0,8 м/с², а при удержании дольше двух секунд держит скорость. В
таблице для неё стоит медиана, близкая к нулю, а её большой разброс учтён в пороге детектора
проскальзывания.

## Пропуски колёсных данных

Пока нет свежих показаний тележек (старше 0,6 с), скорость и путь интегрируются по модели.
Когда колёса возвращаются, скорость сразу берётся по ним. Путь за пропуск поправляется с
расчётом на то, что ошибка скорости модели нарастала линейно:

```
D ← D − (v_модель − v_колёса) · T / 2,   T — длительность пропуска (0,2…60 с)
```

## Проскальзывание и сцепление

Для скорости есть три «голоса»: передняя тележка, задняя тележка и модель. Проскальзывание
одной тележки отсекает строб из раздела про скорость. Одновременное проскальзывание обеих
тележек строб не видит, потому что тележки согласны между собой. Его ловит сравнение с моделью.

Невязка `r = a_колёс − A_модели` сравнивается с адаптивным порогом:

```
|r| > max(0.4,  4σ,  коридор(u, v) + 0.1)   м/с²
```

- `σ` — разброс невязки на обычной езде, оценивается на ходу.
- `коридор(u, v)` — насколько ускорение при этой позиции и скорости обычно отходит от медианы в
  сторону проскальзывания. Для тяги это p95 минус медиана, для торможения — медиана минус p05,
  по 90 записям. Обычно коридор 0,1–0,35 м/с², у позиции −8 — больше 1 м/с².

Боксование проверяется при тяге, юз — при торможении. Подозрение должно продержаться 0,25 с,
скорость должна быть больше 2 м/с.

При срабатывании скорость ведётся по модели от начала подозрения, и одометр поправляется за это
окно задним числом. Модель при этом ограничена физикой, как опорная скорость в противоюзных
системах:

- при боксовании истинная скорость не выше скорости самой медленной тележки;
- при юзе — не ниже скорости самой быстрой.

Возврат к колёсам происходит, когда они снова согласны с оценкой 0,3 секунды, но не позже чем
через 6 секунд.

Срабатывание может оказаться ложным: например, при экстренном торможении рельсовым тормозом
трамвай замедляется сильнее, чем обещает модель. Настоящий срыв сцепления проходит за 1–3
секунды, и разрыв между моделью и колёсами начинает закрываться. Если через 3,5 секунды разрыв
всё ещё у максимума или колёса остановились, оценщик считает тревогу ложной. Он возвращается к
колёсам, убирает из пути набранную разницу и 20 секунд не повторяет срабатывание на той же
позиции контроллера.

Коэффициент сцепления оценивается в момент срыва как реализованное ускорение:
`μ ≈ max(|a|, |A|) / g` (в пределах 0,03…0,5). Дальше оценка возвращается к номиналу 0,25 с
постоянной времени 60 секунд. Относительное скольжение — `(v_колеса − v) / v` для сильнее
отклонившейся тележки.

## Положение на карте

Карта — граф путей. В нём две линии pathgraph от организаторов и то, что мы достроили по GNSS
обучающих записей: разворотные кольца у обеих конечных и два пути отправления на «Таллинской».
Положение задаётся путём, дуговой координатой и направлением:

```
s(t) = s_ref + dir · (D(t) − D_ref)
```

Точка `(x, y, z)` берётся с пути в координате `s` (это ось передней тележки, то есть base_link).
Курс — по хорде от задней тележки (`s − 7,55 м`) к передней, тангаж — по уклону. Переходы
между путями идут по графу.

Начальная выставка. Фиксы GNSS первых 5 секунд переводятся в систему карты (UTM зона 37N минус
(300 000, 6 100 000)). Антенна проецируется на ближайший путь с учётом направления кузова (от
master к rover) и пересчитывается в base_link с учётом выноса антенны. Из каждого фикса
получается «якорь» `s − dir · D(t_фикса)`, итоговое положение — взвешенная медиана якорей.
Веса: master 1,0 (при status 0 — 0,7), rover 0,15, SBAS 0,02. Rover в этих данных заметно хуже
master. Если трамвай стоит вне карты (дальше 12 м от путей), положение ведётся счислением по
прямой с курсом по антеннам, пока трамвай не подойдёт к подходящему пути.

Места остановок. Водители останавливаются у стоп-линий и платформ очень повторяемо, с разбросом
0,1–0,3 м. По обучающим записям найдено 43 таких места (кластеры 1,5 м, не меньше четырёх
остановок). При остановке дольше 5 секунд:

1. Неопределённость пути растёт с пройденным расстоянием: `σ ← σ + 0,0015 · ΔD`.
2. Кандидаты ищутся в стробе `min(8 м, max(2,5 м, 3σ))`.
3. Правдоподобие кандидата — `n · N(d; 0, σ² + σ_м²)`, где `n` — сколько раз там
   останавливались, `σ_м` — разброс места. Если рядом есть более частое место, у менее частого
   вес умножается на 0,1.
4. Место принимается, только если оно в 10 раз вероятнее остальных кандидатов вместе.
5. Поправка — шаг фильтра Калмана: `s_ref ← s_ref + K · (s_места − s)`, `K = σ² / (σ² + σ_м²)`.

Отдельно обрабатывается подтягивание: вторая остановка в пределах 20 м от первой ищется по
точному смещению от неё.

Масштаб колёс иногда заметно другой: 3 сентября путь по колёсам был короче настоящего на
0,6–1,6 %. Такое ловится двумя способами:

- по соседним местам остановок: два интервала подряд (каждый от 150 м) с уходом одного знака
  больше 0,3 % → масштаб поправляется на средний уход;
- по серии остановок, когда ошибка уже больше строба: модель `d = d₀ + r · A` подбирается
  RANSAC по парам остановок. Нужно не меньше четырёх остановок у мест на размахе от 500 м и
  `|r| > 0,35 %`.

Интервалы, где было проскальзывание дольше секунды, в оценку масштаба не идут. Поправка
масштаба ограничена ±2,5 %.

Ветка, которую нельзя наблюдать. На «Таллинской» со стрелки на кольце часть трамваев уходит на
средний путь. Его геометрия восстановлена по трём обучающим записям. Какой путь выбран, по
колёсам и контроллеру не видно: по обучающим записям через стрелку прошли 25 трамваев, 22 по
кольцу и 3 на средний путь. Поэтому после стрелки выдаётся взвешенная точка, которая даёт
минимум ожидаемой квадратичной ошибки:

```
p = (3 + 1) / (25 + 2) ≈ 0.15
P = (1 − p) · P_кольцо(s) + p · P_ветка(s − s_стрелки),   σ² ← σ² + p (1 − p) d²
```

`d` — расстояние между гипотезами. Когда трамвай проехал дальше конца ветки, остаётся только
кольцо. На стоянке вес ветки убывает с постоянной времени 15 секунд: долго в этой зоне стоят
только на кольце.

## Ковариации на выходе

- Дисперсия положения — `max(0,04 м², σ²)` плюс вклад ветки. При счислении вне карты —
  `1 + (0,05 · ΔD)²`.
- Дисперсия скорости — `0,05²` в обычном режиме и `0,5²` при проскальзывании.
